# Task Categories

## 背景

- 创建日期：2026-07-17
- 功能标识：`categorize`
- 需求来源：为任务和习惯提供分类能力，支持官方预设分类和用户自定义分类。分类入口集中在 RichView 的搜索/浏览页，并在主页卡片上提供轻量识别。

## 目标

- 为任务和习惯都支持可选分类，默认不分类。
- 提供一组预设分类，用户也可以创建自定义分类。
- 分类支持图标和颜色；图标与颜色可以在浏览页的分类管理入口中自定义。
- RichView 的搜索页改名为“浏览”，保持原有放大镜 Tab 图标不变，并作为分类查看入口。
- 主页 Deadline 卡片以小图标徽标展示分类，但不改变卡片已有的 Deadline 语义色、进度色和状态色。
- Editor 中通过独立选择 Sheet 为任务/习惯指定分类；该 Sheet 可以新增分类，但不能编辑分类。
- Rich 主页左上角筛选按钮接入分类筛选。
- 保持 WebDAV V2 同步兼容，并为后续 V3 后端同步保留清晰的数据边界。

## 非目标

- 不把分类颜色用于替代 Deadline 卡片的逾期、临期、完成、放弃等语义色。
- 不在分类选择 Sheet 中编辑已有分类；编辑只在浏览页分类管理中发生。
- 不强制迁移已有任务/习惯到某个默认分类。
- 不改变旧版 V1 快照结构；从 V2 投影到 V1 时分类字段可以被丢弃。
- 本阶段不实现云端 V3 后端，只预留资源模型和同步边界。

## 用户场景

1. 用户在创建任务或习惯时保持默认“不分类”，保存后原有流程不受影响。
2. 用户编辑任务或习惯，打开“分类”选择 Sheet，选择一个预设或自定义分类。
3. 用户在分类选择 Sheet 中点击 Toolbar 的 `+`，快速创建一个新分类并立即选中。
4. 用户进入 RichView 的“浏览”页，从分类列表进入某个分类，查看该分类下的任务和习惯。
5. 用户在浏览页分类管理中修改分类图标和颜色。
6. 用户在主页看到 Deadline 卡片右侧或标题附近的小分类图标，但仍能通过原有颜色理解任务状态。
7. 用户点击主页左上角筛选按钮，按分类过滤任务/习惯列表。

## 验收标准

- 新建任务和新建习惯默认 `categoryUID == nil`。
- 任务和习惯均可在 Editor 中选择分类，并可清除为“不分类”。
- 分类选择 Sheet 支持新增分类，不提供编辑入口。
- 浏览页展示分类入口；搜索 Tab 图标保持放大镜，页面文案改为“浏览”。
- 分类详情页同时展示该分类下的任务和习惯，支持现有编辑、归档、删除、打卡等操作。
- 主页卡片展示分类图标；分类颜色只用于徽标，不影响 `DDLStatusStyle` 语义色。
- 主页左上角筛选按钮可选择全部、未分类或具体分类，并对当前任务/习惯视图生效。
- 旧的 WebDAV V2 任务/习惯快照缺少分类字段时可以正常解码，解码结果为无分类。
- 新的 WebDAV V2 快照包含可选分类字段；投影到 V1 时分类字段不写入 V1。
- 分类定义使用独立快照文件同步，避免耦合任务和习惯快照，为 V3 后端资源化同步做准备。

## 风险与约束

- SwiftData 新增字段和实体需要确认轻量迁移行为，避免破坏已有本地数据。
- 同步需要兼容旧客户端：新增字段必须可选，新增分类快照缺失时不能导致整体同步失败。
- 分类删除采用软删除或保留 uid 语义，已有任务/习惯引用失效时 UI 回退为“未分类/未知分类”。
- 卡片组件要只接收展示徽标，不能把分类规则塞进状态色计算。
- 任务、习惯、搜索、主页共用分类展示模型，避免多个页面各自解析颜色和图标。
- 大文件守则：核心 Swift 文件有效代码尽量不超过 1000 行，必要时拆分 Feature 组件。

## 当前故障事实（2026-07-18）

- 浏览页从分类入口进入分类详情时，高概率卡死并最终崩溃，症状集中在 `NavigationStack` 转场与 UIKit 提交事务阶段。
- 新增带分类的任务后，浏览页或首页依赖分类映射的列表会出现临时消失；重启后部分页面才恢复。
- 自定义分类在下一次启动后会消失，说明“分类本体持久化”与“分类缓存/同步回放”至少有一处不稳定。
- 现有实现已经不能视为“功能完成”，本轮工作以稳定性重构为主，不以新增交互为目标。

## 本轮重构目标

- 保证分类定义（预设 + 自定义）在本地存储中可稳定跨启动保留。
- 保证浏览页进入分类详情时不会因页面刷新、导航状态或局部氛围状态回写而卡死。
- 保证任务/习惯写入分类后，首页、浏览页、编辑器和分类详情都能看到一致的分类映射，不需要重启才能恢复。
- 明确分类功能依赖的持久化启动策略：禁止正式运行时静默退回内存库。
- 如需引入迁移或启动期自检，优先保证已有任务/习惯数据不被破坏。

## 持久化专项验收标准

- 每个持久化测试都能使用独立 store；同一 store 必须可关闭并重新打开以模拟重启。
- 创建、修改或清除 Habit 分类时，Habit 与载体 DDL 的分类 UID 不得出现半完成状态。
- 分类 CRUD、预设 bootstrap、软删除和同步回放的每个状态转换均有单测；同步冲突与缺失快照必须有确定的回退结果。
- 功能层不得直接创建 `ModelContext` 读取分类相关数据；持久化读写必须经过受控 store/repository 边界。
- 分类详情卡死必须先由自动化失败用例稳定复现，修复后重复执行该用例及重启/同步并发用例。
