# Home Toolbar Segment Filter

## 背景

- 创建日期：2026-07-16
- 功能标识：`home-toolbar-segment-filter`
- 需求来源：非看板模式首页需要把“任务 / 习惯”切换从内容区上移到顶栏，Rich 模式还要预留首页筛选入口，作为后续任务分类能力的挂载点。

## 目标

- 让经典首页样式（非看板模式）的 `TaskSegment` 切换与添加页保持一致，使用导航栏 `Toolbar` 的分段选择器承载。
- 在 Rich 首页的左上角增加一个筛选按钮占位，先提供稳定入口，再在后续迭代接入任务分类逻辑。
- 将改动限制在 iOS 展示层，不引入数据结构或仓储层变更。

## 非目标

- 不修改看板模式首页（Dashboard Home）的头图、分段切换方式或列表布局。
- 不在本轮实现真实的任务分类筛选规则、筛选弹层或持久化状态。
- 不扩展到 HarmonyOS、Android，或改动添加页自身交互。

## 用户场景

1. 用户在经典首页查看任务与习惯时，希望像添加页那样直接在导航栏顶部切换，而不是滚动到内容区顶部再操作。
2. 用户在 Rich 首页未来需要按任务分类筛选时，界面上已经有一个明确且固定的筛选入口，不需要再重新调整导航栏结构。

## 验收标准

- 当首页处于非看板模式时，“任务 / 习惯”切换显示在导航栏 `principal` 位置，任务与习惯列表都能正常切换。
- 非看板模式首页的内容区顶部不再额外渲染原来的分段控件。
- Rich 首页在非选择模式下左上角显示筛选按钮，当前点击行为保持占位，不引发崩溃或额外交互副作用。
- 现有选择模式工具栏、AI 入口、设置入口不被本轮调整破坏。

## 风险与约束

- 经典首页的顶栏分段控件来自 [HomeView.swift](/Users/aritxonly/Codes/iOS/Deadliner/Deadliner/Features/Home/HomeView.swift) 的子 toolbar，需确认在 Focus 与 Rich 两种宿主导航结构下都能稳定显示。
- Rich 首页左上角新增按钮后，会与现有 AI 按钮共享 leading 区域，需避免导航栏拥挤或覆盖 `principal` 分段控件。
- 当前工作区存在未提交改动，本轮只能在相关首页展示文件上做增量修改，不能回退既有本地变更。
